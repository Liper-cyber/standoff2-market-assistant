# Standoff 2 Market Automation

Личный проект для автоматизации операций на внутриигровом рынке Standoff 2. Приложение управляет Android-эмулятором через Appium, находит элементы интерфейса и распознаёт данные на экране с помощью компьютерного зрения, а информацию об аккаунтах и скинах хранит в PostgreSQL.

> **Статус проекта:** личный экспериментальный проект. Автоматизация может нарушать правила игры или платформы и привести к ограничениям аккаунта. Перед использованием проверьте правила и сначала тестируйте на отдельной среде. Проект не предназначен для торговли реальными активами.

## Демонстрация

[▶ Смотреть видео работы приложения на YouTube](https://youtu.be/SRLDG3gkh2c?si=XHiEM1KqCqA-xOO3)

В видео показаны запуск эмулятора и Appium, распознавание баланса, покупка и продажа скинов, а также обработка наклеек.

## Возможности

- Поиск элементов игрового интерфейса по шаблонам с OpenCV.
- Распознавание чисел и баланса с EasyOCR и обработкой изображений.
- Управление Android-эмулятором через Appium и Selenium.
- Сценарии покупки и продажи внутриигровых скинов.
- Хранение аккаунтов, цен, настроек и связей со скинами в PostgreSQL.
- Tkinter-интерфейс для управления скинами и аккаунтами, а также создания скриншотов областей экрана.

## Технологии

Python · Tkinter · OpenCV · EasyOCR · Tesseract OCR · Pillow · Appium · Selenium · ADB · PostgreSQL · psycopg2

## Требования

- Windows и Python.
- LDPlayer 9 с включённой локальной отладкой ADB. Текущие координаты интерфейса рассчитаны на разрешение эмулятора 1080×1920.
- Node.js и Appium Server с драйвером UiAutomator2 и плагином Images.
- PostgreSQL (SQL-файл проекта подготовлен для PostgreSQL 18).
- Установленный Tesseract OCR.
- Модели EasyOCR в каталоге, указанном в `config/configall.py`.

Эмулятор, Tesseract, Appium и PostgreSQL устанавливаются отдельно и не входят в `requirements.txt`. PyTorch устанавливается как зависимость EasyOCR. Для GPU может понадобиться подходящая сборка PyTorch и CUDA; для работы на CPU проверьте соответствующую настройку OCR в проекте.

## Установка и настройка

Откройте PowerShell в корне проекта и создайте виртуальное окружение:

```powershell
py -m venv venv
.\venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
```

### 1. Настройте эмулятор

Установите LDPlayer 9, создайте виртуальное устройство Android 9 с разрешением 1080×1920, включите локальную отладку ADB, установите Standoff 2 и войдите в тестовый аккаунт.

### 2. Создайте и заполните базу данных

Создайте базу PostgreSQL, затем проверьте `sql/schema.sql`: файл создаёт таблицы и содержит начальные SQL-вставки. Перед применением отредактируйте вставки аккаунтов и других данных под свою базу.

Пример команды из PowerShell (замените имя базы и пользователя на свои):

```powershell
psql -U postgres -d standoff -f sql/schema.sql
```

### 3. Настройте переменные окружения

Создайте локальный файл `.env` в корне проекта:

```dotenv
DB_HOST=127.0.0.1
DB_PORT=5432
DB_NAME=standoff
DB_USER=postgres
DB_PASSWORD=replace_me
APPIUM_HOST=127.0.0.1
```

Укажите свои значения. Не публикуйте `.env` и не добавляйте его в Git.

### 4. Укажите локальные пути

В `config/configall.py` настройте пути к LDPlayer, ADB, Tesseract и моделям EasyOCR, а также локальные параметры устройства и сети. Путь к каталогу моделей должен содержать необходимые модели OCR.

### 5. Установите и запустите Appium

Установите Appium Server, драйвер UiAutomator2 и плагин Images. Запустите сервер с плагином:

```powershell
appium --use-plugins=images
```

## Запуск

Запустить графический интерфейс:

```powershell
python -m TollStandoff
```

Запустить сценарий автоматизации с вводом ID эмулятора:

```powershell
python startFile.py
```

Перед запуском сценария проверьте доступность базы данных, эмулятора и Appium, а также соответствие ID выбранному устройству.

## Работа с интерфейсом

В приложении три вкладки: **«Скины»**, **«Аккаунты»** и **«Скриншот Tool»**. Ниже описаны назначение основных элементов и порядок работы с ними.

### Вкладка «Скины»

![Вкладка «Скины»](docs/img/01-skins-window.png)

Вкладка показывает карточки скинов, сохранённых в базе данных.

- **Поле «Поиск скина»** — фильтрует список по названию.
- **Карточки скинов** — показывают сведения о скине и дают перейти к его редактированию.
- **«Добавить скин»** — открывает форму создания записи. В форме указываются имя, редкость, ссылка на изображение, минимальная и максимальная цена покупки, цена продажи, интервал ожидания скупки и глобальная цена продажи.
- **«Изменить»** — открывает форму редактирования выбранного скина.
- **«Ссылка на фотку»** — адрес или путь к изображению, связанного со скином.

Чтобы добавить скин, нажмите **«Добавить скин»**, заполните поля и сохраните запись. Если изображение берётся из эмулятора, сначала его можно подготовить во вкладке **«Скриншот Tool»**.

### Вкладка «Аккаунты»

![Вкладка «Аккаунты»](docs/img/02-acounts-window.png)

Здесь отображаются карточки аккаунтов из базы данных и скины, привязанные к выбранному аккаунту.

- **Поле поиска** — фильтрует аккаунты по названию.
- **Карточки аккаунтов** — показывают сведения об аккаунте, включая отображаемый баланс.
- **«Добавить скин»** — открывает список скинов для привязки к выбранному аккаунту.
- **«Выбрать»** — показывает связанные с аккаунтом скины в области «Скины аккаунта».
- **«История»** — пока зарезервирована для будущего отображения изменений баланса и скинов.
- **Список «Действия»** — позволяет выбрать сценарий:
  - **«Продажа по обычной цене»** — выполняет цикл покупки привязанных скинов и продажи скинов аккаунта. Цена продажи берётся из поля «Цена продажи».
  - **«Продажа по глобальной цене»** — выполняет тот же тип цикла, используя поле «Глобальная продажа» для цены продажи.
  - **«Рандомная продажа»** — выставляет случайные скины, привязанные к аккаунту. Количество задаётся параметром `count_sell` функции `sell_random_skins` (по умолчанию случайное значение от 80 до 140). При очень большом количестве скинов аккаунт может работать медленно.
  - **«Тест функций»** — запускает тестовый сценарий; для изменения тестируемого действия используется функция `custom_buy` в `main.py`.
- **«Запустить»** — запускает выбранное в списке действие.
- **«Стоп»** — завершает процесс сценария, но не выключает виртуальную машину.

В сценарии покупки используются заданные для скина цены и интервал ожидания. Когда подходящих для покупки скинов пока нет, сценарий может переключаться на продажу. Количество продаж в цикле `TradeByuSell` задаётся параметром `skin_count_sell` (по умолчанию случайное значение от 20 до 25). Поведение и цены зависят от выбранного действия и данных в базе.

### Окно привязки скина к аккаунту

![Окно привязки скина к аккаунту](docs/img/03-add_skin_for_ac-window.png)

В окне отображаются названия скинов и поле поиска.

- **Поле поиска** — помогает найти нужный скин.
- **Список скинов** — выбор записи добавляет связь аккаунта со скином в таблицу `account_skins`.

После выбора связанный скин появляется в области «Скины аккаунта».

### Вкладка «Скриншот Tool»

![Вкладка «Скриншот Tool»](docs/img/04-picture_tool-window.png)

Вкладка позволяет подключиться к эмулятору и сохранить скриншот всего скина или заданной области экрана.

- **X, Y** — координаты верхнего левого угла области.
- **Width, Height** — ширина и высота области.
- **ID NOX** — индекс виртуальной машины LDPlayer.
- **Путь сохранения** — файл, куда будет записан скриншот; кнопка «Обзор» открывает выбор пути. По умолчанию используется `./img/screenshots/region.png`.
- **«Полный скин»** — подставляет координаты из `SKIN_FULL` и снимает область со скином.
- **«Наклейки»** — подставляет координаты из `SKIN_NACKLE` для снимка области наклеек.
- **«Сделать скриншот»** — сохраняет область с заданными координатами.
- **«Подключиться к устройству»** — устанавливает соединение с выбранным эмулятором.
- **Строка статуса** — сообщает о состоянии подключения и операции.

#### Создание скриншота скина

1. Укажите путь сохранения через **«Обзор»** или оставьте значение по умолчанию.
2. Введите индекс эмулятора в поле **«ID NOX»**.
3. Нажмите **«Подключиться к устройству»** и дождитесь подтверждения соединения.
4. Нажмите **«Полный скин»** или **«Наклейки»**, чтобы применить сохранённые координаты и сделать снимок. Для собственной области задайте X, Y, Width и Height и нажмите **«Сделать скриншот»**.

Координаты пресетов находятся в `config/configall.py` в массивах `SKIN_FULL` и `SKIN_NACKLE`. При изменении разрешения эмулятора координаты могут потребовать настройки.

## Ограничения и известные особенности

- Пути к программам, координаты и сетевые параметры привязаны к локальной конфигурации компьютера; перед переносом настройте `config/configall.py`.
- Поиск шаблонов и распознавание зависят от разрешения, языка и состояния экрана, а также от версии игры.
- Сценарии автоматизации могут работать длительными циклами. Контролируйте их работу и проверяйте на тестовых данных перед длительным запуском.
- Запуск нескольких процессов для одного аккаунта может привести к конфликтному управлению одной виртуальной машиной.

## Структура проекта

```text
actions/          поиск шаблонов и действия на экране
config/           настройки приложения, эмулятора, Appium и БД

services/         торговая логика и работа с PostgreSQL
TollStandoff/     графический интерфейс на Tkinter
img/              шаблоны интерфейса, изображения скинов и скриншоты
docs/img/         изображения интерфейса для этого README
sql/schema.sql    создание таблиц и начальные данные
main.py           сценарии автоматизации
startFile.py      запуск сценария с вводом ID эмулятора
requirements.txt  прямые Python-зависимости
```
